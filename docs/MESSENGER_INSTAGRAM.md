# بوتات ماسنجر وإنستجرام — الخطة والربط

> **الحالة (2026-09-21):** المرحلة 1 منفَّذة — للفريق وحده. المرحلتان 2 و3 تنتظران اعتماد Meta.

## لماذا قناة واحدة للاثنين

Meta توحّد ماسنجر ورسائل إنستجرام في **Messenger Platform**: نفس الـSend API
(`POST /me/messages` بتوكن الصفحة)، ونفس شكل الويبهوك (`entry[].messaging[]`)، ونفس
سياسة الـ24 ساعة. لذلك `channels/messenger.py` قناة واحدة ببادئتين:

| | ماسنجر | إنستجرام |
|---|---|---|
| القناة (`bots.channel`) | `messenger` | `instagram` |
| توكن البوت | `fb:<page_id>` | `ig:<ig_user_id>` |
| العميل (peer) | `fb:<PSID>` | `ig:<IGSID>` |
| التوكن التشغيلي | Page Access Token (مختوم `db.seal`) | توكن الصفحة المربوطة نفسه |
| الملفات | مرفق `file` | رابط نصي (إنستجرام لا يستقبل ملفات) |

الحساب الإنستجرامي لازم يكون **احترافياً (Business/Creator) ومربوطاً بصفحة فيسبوك**.

## السياسات التي يفرضها الكود

- **الرد الحر داخل 24 ساعة فقط** من آخر رسالة للعميل (`messaging_type: RESPONSE`):
  البث (`bot_manager.broadcast`) يقتصر على من راسل خلالها، والرد اليدوي من صندوق الوارد
  ومن تليجرام يُرفض بعدها. لا رسائل تسويقية خارج النافذة — المخالفة تُقيّد الصفحة.
- لا Message Tags في المرحلة 1 (`HUMAN_AGENT` يمد النافذة 7 أيام ويحتاج مراجعة Meta).
- صدى رسائلنا (`is_echo`) لا يُعامل كوارد، وإعادة إرسال Meta لنفس الحدث لا تتكرر (`mark_msg_seen`).

## المراحل

### المرحلة 1 — للفريق (منفَّذة)
كارت «بوت ماسنجر وإنستجرام» في الداشبورد للأدمن والدعم فقط (`/meta/connect` بـ
`require_roles`). يُلصق Page ID + توكن:
- **توكن صفحة** من System User (الأفضل — لا ينتهي)، أو
- **توكن مستخدم** من Graph API Explorer: الخادم يبدّله بطويل الأمد (60 يوماً) بسرّ التطبيق،
  ثم يأخذ توكن الصفحة من `/me/accounts` — وتوكن صفحة من توكن مستخدم طويل **لا ينتهي**.

ثم `POST /{page}/subscribed_apps` (messages · messaging_postbacks · messaging_referrals)
ويُنشأ بوت ماسنجر و/أو إنستجرام بنفس القالب وعقل البوت وصندوق الوارد وتنبيهات تليجرام.

**يعمل بوصول قياسي** — لأن صاحب الصفحة له دور في التطبيق. لا يحتاج مراجعة Meta.

### المرحلة 1.5 — لوحة تحكم الأدمن «/admin/meta» (منفَّذة 2026-09-21)
للأدمن وحده (`require_roles("admin")` — ولا حتى الدعم):
- **صفحة المنصة تُحفظ مرة**: Page ID + توكن ← `meta_page_id` و`meta_page_token` (مختوم) في
  platform. «حدّث واشترك» بلا توكن جديد يعيد الاشتراك بالمحفوظ. التوكن لا يعود للمتصفح
  (مستثنى من صفحة إعدادات المنصة أيضاً).
- **حقول الاشتراك** (`meta_pages.ALL_FIELDS` — كل ما في «Edit Page Subscriptions»): اختيار حر،
  و«المقترح» = ما يعالجه BotYalla. Meta ترفض الطلب كله لو حقل يحتاج إذناً — فنجرّب حقلاً حقلاً
  ونعرض المرفوض بسببه ونشترك في الباقي.
- **المساعد الرسمي** على ماسنجر وإنستجرام من التوكن المحفوظ (`platform_kb` + ذكاء) بضغطة، ويبدأ فوراً.
- **ربط صفحة لمستخدم**: تُنشأ البوتات في حسابه وتبدأ فوراً (الميزة تُمنح يدوياً في هذه المرحلة).
- كل بوتات الصفحات مع «إعادة الاشتراك»، و**سجل الأحداث** (`meta_events`، آخر 3000).

**ما يعالجه BotYalla من الأحداث** (`bot_manager.meta_side_events`):
| الحدث | التصرف |
|---|---|
| `message_echoes` من إنسان (Business Suite/الموبايل) | يُسجَّل رداً بشرياً ويسكت البوت في المحادثة |
| صدى البوت نفسه (`app_id` تطبيقنا) | يُهمل — مسجَّل عند إرساله |
| `messaging_handovers` | الصفحة أخذت المحادثة ← بشري · أعادتها لتطبيقنا ← البوت |
| `standby` | الرسالة تُسجَّل في الصندوق بلا رد |
| `messaging_optins/optouts` (STOP) | لا بث لهذا العميل |
| قراءة · تسليم · تفاعل · تعديل · تعليقات · تسميات · سياسات · نماذج عملاء | سجل الأحداث |
| حدث لصفحة بلا بوت/بوت متوقف | `unrouted` في السجل بدل أن يضيع |

### المرحلة 2 — الربط بضغطة (بعد الاعتماد)
نافذة Facebook Login for Business بتكوين **صفحات** مستقل (`META_PAGES_CONFIG_ID`) بنفس
مسار النافذة المنبثقة الموجود لواتساب (`dialog_url` + `/…/return`) ← `code` ← توكن مستخدم
← قائمة الصفحات ← العميل يختار ← **`meta_pages.connect` نفسها**. ثم يُفتح الكارت لباقات
مدفوعة (قرار تسعير: ضمن «التاجر» أم إضافة؟).

### المرحلة 3 — الطرح الكامل
صفحة هبوط/قطاع · تعليقات إنستجرام → رد خاص (Private Replies) · زر «ابدأ» وقائمة ثابتة
(Persistent Menu) · روابط `m.me/<page>?ref=seg-…` و`ig.me/m/<user>?ref=…` للإعلانات
(`referral` يُقرأ بالفعل كرمز شريحة).

## خطوات Meta المطلوبة (تطبيق `1337778974883863`)

1. **Messenger** (مضاف) ← «إعدادات» ← **Webhooks**: Callback URL `https://botyalla.com/wh/meta`
   + نفس Verify Token، واشترك في: `messages`, `messaging_postbacks`, `messaging_referrals`.
2. أضف منتج **Instagram** ← إعداداته ← نفس الويبهوك، واشترك في `messages`, `messaging_postbacks`.
3. في إعدادات إنستجرام على الموبايل: الإعدادات ← الخصوصية ← الرسائل ← فعّل
   **Allow access to messages** (مطلوب لتصل رسائل إنستجرام للتطبيق).
4. الحساب الإنستجرامي احترافي ومربوط بالصفحة (إعدادات الصفحة ← الحسابات المرتبطة).
5. التوكن (المرحلة 1): Graph API Explorer ← التطبيق `1337778974883863` ← User Token بأذونات
   `pages_show_list`, `pages_messaging`, `pages_manage_metadata`, `instagram_basic`,
   `instagram_manage_messages`, `business_management` ← Generate.
6. **App Review (للمرحلة 2)**: وصول متقدم لـ `pages_messaging`, `pages_manage_metadata`,
   `instagram_manage_messages`, `instagram_basic` بنفس أسلوب مراجعة واتساب (نداء API + فيديو).

## حدود المرحلة 1 المعروفة
- وسائط مكتبة الوسائط تُرسل كتعليق وأزرار فقط (الرفع عبر Attachment Upload API لاحقاً).
- لا اسم للعميل في صندوق الوارد (يحتاج `GET /{psid}?fields=name` — لاحقاً).
- لا عدّاد استهلاك: Meta لا تحاسب على رسائل الصفحات.
