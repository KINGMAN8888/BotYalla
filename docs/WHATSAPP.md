## الخلاصة قبل التفاصيل

**العمل التقني أسهل مما تتوقّع. العمل غير التقني أصعب بكثير.**

محرّك المحادثات عندك 128 سطراً فقط، ومنطقه الفعلي (تقدّم الخطوات، حفظ الإجابات) لا علاقة له بتليجرام — الارتباط كله في طبقة الإرسال. التجريد ممكن وواقعي.

لكن واتساب ليس «تليجرام بأيقونة خضراء». ثلاثة فروق تغيّر المنتج نفسه:

| | تليجرام | واتساب Cloud API |
|---|---|---|
| **الاتصال** | Polling (خيط دائم) | **Webhook** (يدفع إليك) |
| **التكلفة** | مجاني تماماً | **مدفوع لكل رسالة/محادثة** |
| **المراسلة الحرة** | دائماً | **24 ساعة فقط** بعد آخر رسالة من العميل |
| **هوية المستخدم** | `user_id` رقمي | رقم هاتف |
| **البدء** | توكن من BotFather (دقيقة) | حساب أعمال موثّق + رقم + مراجعة Meta (أيام) |

**الفرق الثالث هو الأخطر تجارياً**: بعد 24 ساعة من صمت العميل لا يمكنك مراسلته إلا بقالب معتمد مسبقاً من Meta. هذا يعني أن **ميزة البث (Broadcast) الحالية لا تعمل على واتساب** بشكلها الحالي.

## 1) ما يجب تغييره في الكود

### 1.1 المشكلة الحاسمة: حالة المحادثة في الذاكرة

`flow_engine.py` يخزّن موضع العميل في الفلو داخل `ctx.user_data` — ذاكرة python-telegram-bot:

```python
ctx.user_data["fi"] = i              # رقم الخطوة الحالية
ctx.user_data["fdata"][var] = ans    # الإجابات المتراكمة
```

هذا يعمل مع تليجرام لأن العملية حيّة دائماً. **لا يعمل مع واتساب إطلاقاً**: كل رسالة تصل كطلب HTTP مستقل، ولا يوجد `ctx` يحمل تاريخاً.

وهي مشكلة قائمة حتى بدون واتساب: **أي إعادة تشغيل للخدمة تُفقد كل المحادثات الجارية** في منتصفها. العميل الذي كان في الخطوة 3 من 5 يجد البوت نسي كل شيء.

**الحل — جدول حالة:**

```sql
CREATE TABLE IF NOT EXISTS chat_state(
    bot_id      INTEGER NOT NULL,
    peer        TEXT NOT NULL,        -- tg:12345  |  wa:201001234567
    step        INTEGER NOT NULL DEFAULT 0,
    data_json   TEXT NOT NULL DEFAULT '{}',
    updated_at  INTEGER NOT NULL,
    PRIMARY KEY(bot_id, peer),
    FOREIGN KEY(bot_id) REFERENCES bots(id) ON DELETE CASCADE
);
```

نفّذ هذا **أولاً وقبل واتساب** — يصلح عيباً حالياً، ويجعل تليجرام وواتساب يتشاركان نفس المنطق.

> احذف الحالات الأقدم من 24 ساعة دورياً، وإلا نما الجدول بلا حد.

### 1.2 مخطط قاعدة البيانات

عمودان يفترضان تليجرام:

| الموضع | المشكلة | التعديل |
|---|---|---|
| `bots.token` (UNIQUE) | واتساب لا يستخدم توكناً واحداً — يحتاج `phone_number_id` + `waba_id` + access token | أضِف `channel TEXT NOT NULL DEFAULT 'telegram'`، واسمح بـ `token` فارغاً للواتساب مع وضع بياناته في `config_json` |
| `bot_users.tg_user_id` INTEGER | واتساب يعرّف بالهاتف (نص) | أضِف `peer TEXT` واملأه من `tg_user_id` في الهجرة |

الهجرة داخل `database._migrate` كما تفرض `AGENTS.md §2`:

```python
bcols = {r[1] for r in c.execute("PRAGMA table_info(bots)").fetchall()}
if "channel" not in bcols:
    c.execute("ALTER TABLE bots ADD COLUMN channel TEXT NOT NULL DEFAULT 'telegram'")

ucols = {r[1] for r in c.execute("PRAGMA table_info(bot_users)").fetchall()}
if "peer" not in ucols:
    c.execute("ALTER TABLE bot_users ADD COLUMN peer TEXT")
    c.execute("UPDATE bot_users SET peer='tg:'||tg_user_id WHERE peer IS NULL")
```

> `bots.token` عليه قيد `UNIQUE` وSQLite لا يسمح بحذف قيد بـ `ALTER`. بوتات واتساب ستحتاج قيمة فريدة — استخدم `wa:<phone_number_id>` كتوكن صوري بدل إعادة بناء الجدول.

### 1.3 تجريد القناة

الفكرة: افصل **ما يُقال** عن **كيف يُرسَل**. المنطق يبقى واحداً، والقناة تتبدّل.

```
channels/
  base.py        # الواجهة المجرّدة
  telegram.py    # يغلّف الكود الحالي
  whatsapp.py    # جديد
```

```python
# channels/base.py
class Channel:
    """كل قناة تنفّذ هذه الواجهة. المنطق أعلاها لا يعرف أي قناة يستخدم."""

    async def send_text(self, peer, text): ...
    async def send_buttons(self, peer, text, options): ...
    async def send_image(self, peer, url, caption=None): ...

    def normalize(self, raw) -> dict | None:
        """يحوّل رسالة واردة إلى شكل موحّد:
        {peer, text, name, kind: 'text'|'button'|'start'}"""
```

ثم يُعاد كتابة `flow_engine` ليعمل على هذه الواجهة:

```python

    """محرّك الفلو — لا يعرف تليجرام ولا واتساب."""
    st = db.get_chat_state(bot_row["id"], msg["peer"])
    ...
    await channel.send_text(msg["peer"], step["prompt"])
    db.set_chat_state(bot_row["id"], msg["peer"], step_index, data)
```

**ما يُعاد استخدامه كما هو:** كل `templates_bot.py` (القوالب والمنيو والحجوزات) · `database.py` بالكامل · التحليلات · لوحة التحكم · نظام الباقات والدفع.

**ما يُعاد كتابته:** طبقة الإرسال في `flow_engine.py` فقط (~60 سطراً).

### 1.4 قيود واتساب على الأزرار

ليست خرائط مفاتيح حرّة كتليجرام:

| النوع | الحد | الاستخدام |
|---|---|---|
| Reply buttons | **3 أزرار**، 20 حرفاً للنص | خطوات `buttons` القصيرة |
| List message | **10 عناصر** (حتى 10 أقسام) | المنيو و FAQ |

الفلو الذي فيه 5 خيارات **سينكسر صامتاً** على واتساب. يلزم تحقّق عند الحفظ في باني الفلو: إمّا تحذير للمستخدم، أو تحويل تلقائي لقائمة عند تجاوز 3.

### 1.5 Webhook

```python
@app.route("/wh/whatsapp", methods=["GET", "POST"])
def whatsapp_webhook():
    if request.method == "GET":                     # تحقق Meta عند الربط
        if request.args.get("hub.verify_token") == db.get_platform("wa_verify_token"):
            return request.args.get("hub.challenge", ""), 200
        abort(403)

    # التوقيع إلزامي: أي شخص يعرف الرابط يستطيع تزوير رسائل بدونه
    if not verify_meta_signature(request.headers.get("X-Hub-Signature-256"),
                                 request.get_data()):
        abort(403)
    ...
```

**ثلاثة أشياء إلزامية هنا:**

1. **تحقّق التوقيع** (`X-Hub-Signature-256` بـ HMAC-SHA256 مع App Secret). بدونه أي شخص يعرف الرابط يحقن رسائل مزيّفة في بوتات عملائك.
2. **استثنِ المسار من CSRF.** `_csrf_protect` يرفض كل POST بلا توكن — وMeta لا ترسل توكناً. أضِف استثناءً صريحاً لهذا المسار **فقط**، والتوقيع يحلّ محلّ الحماية.
3. **ردّ 200 فوراً.** Meta تعيد المحاولة عند التأخّر أو الخطأ، فتتضاعف الرسائل. استقبل، ضَع في طابور، وردّ — ثم عالِج.

## 2) الجانب غير التقني — وهو الأصعب

### 2.1 ما يحتاجه كل عميل

| المتطلّب | الوقت | ملاحظة |
|---|---|---|
| Meta Business Account | ساعات | |
| توثيق النشاط (Business Verification) | **أيام إلى أسابيع** | يحتاج سجلاً تجارياً |
| رقم هاتف | فوري | **غير مسجّل على واتساب عادي** — وهذه عقبة حقيقية: معظم أصحاب الأنشطة رقمهم مستخدم بالفعل |
| مراجعة قوالب الرسائل | ساعات إلى أيام | لكل قالب على حدة |

قارن ببوت تليجرام: **دقيقة واحدة** عبر BotFather.

هذا يعني أن رسالة «بوتك جاهز في دقائق» لا تنطبق على واتساب. عدّل توقّعات العميل صراحة في الواجهة وإلا تحوّل الفرق إلى شكاوى دعم.

### 2.2 مساران للتنفيذ

**المسار أ — العميل يربط رقمه بنفسه**
تسجّل كـ Tech Provider في Meta وتستخدم **Embedded Signup** ليربط العميل حسابه من داخل منصتك. أنت لا تدفع تكلفة رسائله.

- ✅ التكلفة على العميل لا عليك · قابل للتوسّع
- ❌ تسجيل Tech Provider مطلوب · رحلة إعداد أطول للعميل

**المسار ب — أرقامك أنت**
تشتري الأرقام وتديرها، وتبيع «بوت واتساب جاهز».

- ✅ العميل يبدأ فوراً بلا إعداد
- ❌ **أنت تتحمّل تكلفة كل رسالة** · لا يتوسّع بلا تسعير محسوب بدقة

**التوصية:** ابدأ بالمسار ب لأول 10–20 عميل — تتعلّم التكلفة الحقيقية من فواتير فعلية. ثم انتقل إلى أ عند إثبات الطلب.

### 2.3 التسعير — تحذير جدّي

باقاتك الحالية (199/499 جنيه شهرياً) **مبنية على أن التشغيل مجاني**، لأن تليجرام مجاني. واتساب ليس كذلك.

> **تحقّق من [أسعار Meta الرسمية](https://developers.facebook.com/docs/whatsapp/pricing) بنفسك.** التسعير تغيّر أكثر من مرة (من محادثة إلى رسالة)، ويختلف بالدولة وبنوع الرسالة. لا تبنِ على رقم من ذاكرتي أو من مقال قديم.

الخطر الملموس: عميل على باقة 199 جنيه يستقبل آلاف الرسائل → **تكلفتك تتجاوز اشتراكه**. المنصة تخسر مع كل عميل ناجح.

**إجراءات لازمة قبل أي عميل واتساب:**

1. **عدّاد رسائل لكل بوت** — لا تطلق بلا قياس
2. **حدّ شهري لكل باقة** + سلوك واضح عند التجاوز (إيقاف/تنبيه/رسوم إضافية)
3. **باقة واتساب منفصلة** بسعر يعكس التكلفة، لا إضافة مجانية للباقات الحالية
4. **لوحة تكلفة للمالك** — تعرف ربحك لكل عميل قبل أن تكتشفه من الفاتورة

نظام التسعير الذي بنيناه (`plan_overrides` وتجاوزات المالك) يجعل التعديل سهلاً — لكنه لن يخبرك بالتكلفة. القياس مسؤوليتك.

### 2.4 نافذة الـ 24 ساعة تكسر البث

`manager.broadcast()` يرسل لكل المشتركين. على واتساب هذا **مخالفة** إن مرّ أكثر من 24 ساعة على آخر رسالة من العميل.

البدائل:
- قوالب تسويقية معتمدة مسبقاً (تكلفة أعلى + مراجعة لكل قالب)
- تقسيم الجمهور: من راسلك خلال 24 ساعة يتلقّى رسالة حرّة، والباقي عبر قالب
- تعطيل البث للواتساب في الإطلاق الأول (الأبسط والأسلم)

**الأهم:** إرسال رسائل مزعجة يؤدي إلى تقييد الرقم أو حظره من Meta. رقم محظور = عميل خسرته وسمعة تضرّرت.

## 3) خطة التنفيذ

### المرحلة صفر — قبل أي كود (يوم)
تحقّق أن السوق يريدها. اتصل بعشرين من أصحاب الأنشطة واسأل: «هل رقم واتساب نشاطك مستخدم حالياً على تطبيق واتساب العادي؟» إن كانت الإجابة «نعم» من معظمهم، فالعقبة الأولى ليست الكود.

### المرحلة 1 — حالة المحادثة في القاعدة (2–3 أيام)

**✅ مُنفَّذة.** جدول `chat_state` + `db.get/set/clear_chat_state` + `purge_stale_chat_state` تُنظّف المحادثات المهجورة كل 6 ساعات مع حلقة التذكيرات.
جدول `chat_state` + نقل `flow_engine` إليه. **يُشحن وحده ويُصلح عيباً قائماً** في تليجرام (فقدان المحادثات عند إعادة التشغيل). لا يحتاج واتساب إطلاقاً.

### المرحلة 2 — تجريد القناة (3–4 أيام)

**✅ مُنفَّذة.** `channels/{base,telegram,whatsapp}.py`. `flow_engine.handle_message` صار مجرّداً، و`build_flow` مجرّد ربط لتليجرام.
`channels/base.py` + `channels/telegram.py` يغلّف الموجود. **لا سلوك جديد** — الاختبارات الحالية يجب أن تمرّ كما هي، وهي دليلك أن التجريد لم يكسر شيئاً.

### المرحلة 3 — واتساب بحساب واحد (أسبوع)

**✅ مُنفَّذة.** `/wh/whatsapp` بتوقيع `X-Hub-Signature-256`، **يفشل مغلقاً** بلا سرّ مضبوط، والمعالجة تُسلَّم لحلقة المدير بلا حجب حتى يعود 200 فوراً.
رقمك أنت. Webhook + `channels/whatsapp.py` + إرسال نصوص وأزرار. اختبر بنفسك على بوت حقيقي.

### المرحلة 4 — إتاحته للعملاء (أسبوع)

**✅ مُنفَّذة.** اختيار القناة في معالج الإنشاء + عمود `bots.channel` + عدّاد رسائل شهري لكل بوت (`usage_msgs`) وحدّ لكل باقة، مع منع واتساب على المجانية.
`channel` في نموذج إنشاء البوت · توثيق خطوات Meta بلغة مفهومة · عدّاد الرسائل والحدود · باقة واتساب.

### المرحلة 5 — Embedded Signup ✅ (2026-09-19)

**✅ مُنفَّذة** بعد اعتماد BotYalla كمزوّد خدمة تقنية من Meta: `wa_signup.py` + `POST /whatsapp/es/finish` + زر
«اربط رقم واتساب بضغطة» في خطوة واتساب. الخادم يبدّل `code` بسرّ التطبيق، **يتحقّق** أن الرقم ضمن أرقام
الـWABA الممنوحة، يشترك في الويبهوك (`subscribed_apps`)، ويسجّل الرقم (`/register` بـPIN يُحفظ مع البوت).
الإعداد: `META_APP_ID` و`WA_ES_CONFIG_ID` في `.env`. اختبارات: `tests/test_wa_signup.py`.

(النص التالي هو التخطيط الأصلي قبل التنفيذ.)

**⛔ لم تبدأ** عمداً. سقالة `/api/wa_auth` التي كانت تُنشئ بوتاً بـ `wa:1234567890` وهمي حُذفت — كانت تنتج بوتات لا تعمل وتتصادم على قيد `UNIQUE`.
عند إثبات الطلب فقط. هذا استثمار كبير لا يُبرَّر قبل وجود عملاء يدفعون.

## 4) ما يجب اختباره

نفس منهج `AGENTS.md §5` — Flask test client بلا واتساب حقيقي:

```python
# stub لطبقة الإرسال
channels.whatsapp.WhatsAppChannel.send_text = lambda self, peer, text: sent.append((peer, text))
```

**حالات إلزامية:**

- webhook بتوقيع خاطئ → **403**، ولا تُنشأ أي رسالة
- نفس الرسالة مرّتين (Meta تعيد المحاولة) → **معالجة واحدة** لا مضاعفة
- الفلو يكمل عبر عدة طلبات HTTP منفصلة (هذا اختبار الحالة الحقيقي)
- خطوة `buttons` بأكثر من 3 خيارات → تتحوّل لقائمة أو تُرفض بوضوح، لا تنكسر صامتة
- بوت تليجرام وبوت واتساب لنفس المالك يعملان معاً بلا تداخل حالة
- عزل الملكية: `_owned()` يبقى ساري المفعول على بوتات واتساب

## 5) قرار قبل البدء

اسأل نفسك بصدق: **هل مشكلتك أن العملاء يطلبون واتساب، أم أن الاكتساب صعب؟**

لو كانت الثانية، فواتساب لن يحلّها — وستكون قد أنفقت أسابيع على قناة تكلّفك مالاً بدل قناة مجانية تعمل. أرخص اختبار: أضف سؤالاً واحداً لنموذج «بوت مخصّص» — «أي قناة تفضّل؟» — واقرأ الإجابات بعد شهر.

الكود سيكون جاهزاً حين تحتاجه. المرحلة 1 وحدها تستحق التنفيذ الآن بصرف النظر عن قرار واتساب.

## 6) ما يلزم لتشغيله فعلياً

الكود جاهز، لكن واتساب لن يستقبل رسالة واحدة قبل هذه الخطوات — بالترتيب:

1. **لوحة الأدمن ← إعدادات المنصة ← WhatsApp Cloud API**: اضبط `Verify Token` (أي نص من
   اختيارك) و`App Secret` (من Meta ← App settings ← Basic).
   بدونهما `/wh/whatsapp` يرفض **كل** الطلبات بـ 403 عمداً: المسار مستثنى من CSRF،
   فالتوقيع هو حارسه الوحيد، والفشل المفتوح هنا يعني نقطة دخول عامة.
2. **في Meta**: اضبط الويبهوك على `https://<نطاقك>/wh/whatsapp` بنفس الـ Verify Token،
   واشترك في حقل `messages`.
3. **إنشاء البوت**: لوحة التحكم ← بوت جديد ← واتساب ← الصق `Phone Number ID` و`Access Token`.
   البيانات تُتحقَّق من Meta فوراً — التوكن الخاطئ يُرفض بدل أن يُنشئ بوتاً ميتاً.
4. **إشعارات العملاء الجدد**: بوت واتساب لا يملك رابط ربط مثل تليجرام. اربط تليجرام من
   صفحة «حسابي» فتصلك الإشعارات عبر بوت المنصة، أو ضع معرّفك في إعدادات البوت.

## 7) الحمايات المطبَّقة

### المالية

- **عدّاد شهري لكل بوت** في `usage_msgs`، والحدّ على مستوى الحساب لا البوت.
  الحجز والفحص في جملة `UPDATE` واحدة فلا يتسلّل إرسال زائد بين خيطين.
- **الباقات**: مجانية = بلا واتساب · احترافية = 1000 رسالة صادرة شهرياً · أعمال = 5000.
  الأرقام في `plans.py` وتُعدَّل من مكان واحد.
- عند نفاد الرصيد يتوقف الإرسال، ويصل تنبيه لصاحب البوت وللأدمن **مرة واحدة في الشهر**
  لا مع كل رسالة.
- الباقة المجانية لا تستطيع إنشاء بوت واتساب أصلاً — الفحص في الخادم لا في الواجهة فقط.

### القوالب المعتمدة

- صفحة `/bot/<id>/templates`: عرض القوالب بحالتها من Meta (معتمد / قيد المراجعة /
  مرفوض مع سبب الرفض)، وإنشاء قالب جديد، وحذفه.
- القوالب تُدار على **WABA ID** لا على Phone Number ID. الرقمان متشابهان ويُخلط
  بينهما دوماً، فنتحقّق باستدعاء فعلي قبل الحفظ لا بالشكل.
- التحقق المحلي يسبق أي نداء لـ Meta: اسم بحروف صغيرة فقط، متغيّرات `{{1}}` ثم
  `{{2}}` بلا فجوات، ولا متغيّرات خارج نص القالب، وحدود الأطوال. كل رفض هنا يوفّر
  على العميل انتظار المراجعة ثم رفضاً غامضاً من Meta.
- صفحة الحملة صار فيها وضعان: **نص حر** (داخل النافذة فقط) و**قالب معتمد**
  (يصل للجميع). المتغيّرات تُملأ من الصفحة وتُرسل لكل المستلمين.
- إرسال القوالب يمرّ بعدّاد الاستهلاك مثل أي رسالة — القوالب مدفوعة أيضاً.

### وسائط العملاء

- نوع خطوة `media` في باني الفلو: العميل يرسل صورة أو تسجيلاً صوتياً بدل الكتابة،
  والملف يظهر مع بياناته في صفحة البوت (الصور مصغّرات، الصوت مشغّل في مكانه).
- تنزيل واتساب خطوتان تفرضهما Meta: المعرّف يعطي رابطاً صالحاً **5 دقائق**، والرابط
  لا يُفتح إلا بترويسة `Authorization`. والوارد يبقى قابلاً للتنزيل **7 أيام** —
  لذلك ننزّل لحظة وصول الويبهوك لا لاحقاً.
- **النوع من بايتات الملف لا من ترويسة المُرسِل.** ملف تنفيذي مُعلَن كصورة يُرفض،
  والاسم على القرص مولَّد داخلياً — اسم العميل لا يلمس نظام الملفات.
- الملفات خارج `static/` وتُقدَّم فقط عبر `/bot/<id>/media/<mid>` بشرط ملكية البوت
  في الاستعلام نفسه. غير الصور والصوت تُنزَّل ولا تُفتح داخل النطاق.
- **حصة شهرية لكل حساب** (مجانية 100 · احترافية 2000 · أعمال 10000) وسقف لكل ملف.
  القرص مورد محدود على السيرفر، وبلا حصة يكفي عميل واحد لملئه.
- ملفات محادثات لم تكتمل تُنظَّف بعد 7 أيام؛ المرتبط بـ lead يبقى.

### التشغيلية

- **نافذة الـ24 ساعة**: البثّ على واتساب يشمل فقط من راسل البوت خلالها
  (`bot_users.last_in_at`). المخالفة تُعاقَب على مستوى الرقم لا الرسالة.
- **منع التكرار**: Meta تُعيد إرسال الويبهوك عند أي تأخّر. `seen_msgs` يضمن أن الإجابة
  تُعالَج مرة واحدة، وإلا تقدّم الفلو خطوة زائدة وفسد الـ lead.
- **الرد فوري**: الويبهوك يعود 200 ويُسلّم المعالجة لحلقة المدير بلا انتظار.
- **كل رسائل الدفعة** تُعالَج، ولأكثر من رقم في الدفعة الواحدة.
- **حدود الأزرار**: أكثر من 3 خيارات أو خيار أطول من 20 حرفاً يُعرض كقائمة مرقّمة،
  والمحرك يقبل الرقم كإجابة — بدل اقتطاع صامت يمنع مطابقة الإجابة إلى الأبد.
- **الوسائط** (صورة/صوت/موقع) لا تُحفظ كإجابة فارغة ولا تقفز خطوة — يُطلب نص.
- **تحديثات الحالة** (`statuses`) تُتجاهل ولا تُعامَل كرسائل واردة.
- **تجديد التوكن**: توكنات Meta المؤقتة تنتهي خلال 24 ساعة. حقل في إعدادات البوت
  يقبل توكناً جديداً بعد التحقق منه.

## 8) ما زال ناقصاً

- **Embedded Signup** — الربط يدوي. لا يُبرَّر قبل وجود عملاء يدفعون.
- **باقة واتساب مستقلة** — الحدود اليوم ملحقة بالباقات القائمة. إن ثبت الطلب فباقة
  خاصة أوضح تسعيراً.
- **تكلفة فعلية مقابل الاشتراك** — العدّاد يحصي الرسائل لا الجنيهات. Meta تسعّر
  بالمحادثة لا بالرسالة وتختلف بالدولة والفئة، فراجع تسعيرها الرسمي وعايِر الأرقام
  في `plans.py` عليه قبل التوسّع.
